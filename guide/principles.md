# 设计原则

<span class="level level-must">🔴 第 1 节 · 强制</span>

以下 4 条原则是全规范的总纲，其余章节的数值与组件规则都可以视为它们的落地方式。当具体规则未覆盖某个场景时，回到这 4 条来判断。

## 原则清单

<ul class="rules">
  <li class="must"><b>一致优先</b>：相同功能在不同页面保持相同外观与交互。</li>
  <li class="recommend"><b>克制装饰</b>：颜色、阴影、动效服务于信息层级。</li>
  <li class="must"><b>状态完整</b>：必须定义默认、悬停、按下、禁用、加载、错误等状态。</li>
  <li class="must"><b>可验证</b>：数值和规则应能被代码检查或走查清单验证。</li>
</ul>

## 逐条说明

### 一致优先 🔴

同一类信息在系统各处使用同一套表达：主操作永远是主按钮，危险操作永远是红色，删除确认永远在弹窗右侧。用户不需要在页面之间重新学习。

判断方法：把两个页面的同类元素截图并排放，如果不看上下文分不出哪个属于哪个页面，说明一致。

### 克制装饰 🟡

颜色、阴影、动效只用来表达层级和状态，不用于表达「好看」。一个页面里出现三种以上的强调色，通常是装饰过度。

- 阴影只用于浮层（卡片、弹窗、下拉），平面内容不加阴影；
- 动效只用于状态切换与空间关系，时长统一 `200ms`；
- 同屏最多一个主按钮（见[按钮](/components/button)）。

### 状态完整 🔴

组件交付时必须同时交付状态。以下 6 个状态是底线：

| 状态 | 触发条件 | 设计要求 |
| --- | --- | --- |
| Default | 无交互 | 基准样式 |
| Hover | 鼠标悬停 | 背景或边框变化，不明显改变尺寸 |
| Active | 按下 | 比 hover 更深一档的反馈 |
| Disabled | 不可用 | 降低对比度，`cursor: not-allowed` |
| Loading | 异步进行中 | 阻止重复提交，给出进度反馈 |
| Error | 校验失败 | 用 `--color-danger` 表达，并说明原因 |

### 可验证 🔴

规范里写下的每一条都要能被检查，否则无法执行。可验证的写法：

- ✅「正文 14px / 行高 1.5」——可被样式检查；
- ✅「同一区域最多一个主按钮」——可被走查；
- ❌「界面要清爽美观」——不可验证。

## 适用范围

| 项目 | 内容 |
| --- | --- |
| 适用端 | Web 端（PC 浏览器） |
| 适用角色 | UI 设计师、前端开发、测试、产品经理 |
| 不在范围 | 移动端、小程序、原生客户端、宣传物料 |
| 唯一源文件 | `公司产品 UI 设计规范.md`；Trae 规则从第 9 节派生，不单独维护数值 |
